# Site financials delivery and continuation plan

Follow this plan on `feat/financial-purchase-review` in `jaideepdhanoa/distributed-sites-map`. Start with AGENTS.md and DESIGN.md. The private November 25 Site Financials Assessment in the owner's files contains the worked site cases and card concept. Keep site-specific evidence and actual financial figures in the signed-in application and private assessment.

## Delivery sequence

1. Build one financial summary for operating pipeline sites, including linked census records. Provide a stable Financials entry on the record, pin, shortlist and Compare. Show original measure, period, basis, source, package status, confirmed zero, loss, withheld, missing, unavailable and inapplicable states. Retain the statement grid, citations, checklist, comments and existing requests.
2. Read workbook inputs and outputs by header. Make business cash, carrying cost, cash-only price support, network target ceiling and land-value constraint individually inspectable. Distinguish the workbook EBITDA from normalized evidence, seller claims, forecasts and reviewer overrides. Check signs, annual period, transaction scope and usable layout before presenting a conclusion. Keep the workbook assumptions traceable and avoid emitting private inputs into public build artifacts.
3. Bring compact evidence and purchase measures to the map, viewport list, shortlist and Compare. Allow reviewers to inspect and compare layout assumptions for retained operations, recurring losses, power costs and interruption. Retain a recoverable scenario and original evidence identity, and indicate changed inputs. Use the existing access model, controls and saved decision workflow.
4. Verify the sparse, loss, zero-ceiling, conflicting-basis, package-only and unresolved-layout paths. Test formulas against the worksheet, desktop and phone navigation, keyboard/focus, source and return links and permissions. Use synthetic financials in public tests and CI evidence.
5. Open the PR, review preview screenshots, observe required checks, merge, and confirm the deployed release. Record the exact PR, tests and remaining limitations in the handoff. No external outreach or changes to deal stages or workbook cells.

## Resume

Fetch the latest main and feature branch, inspect their diff and the PR checks. Work from the first incomplete acceptance item. The Git history and PR are the delivery log. A release is complete only after the implemented paths and deployment have been verified.
